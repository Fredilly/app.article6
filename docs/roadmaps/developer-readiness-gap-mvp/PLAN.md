# Developer Readiness Gap MVP

SSOT: `docs/roadmaps/developer-readiness-gap-mvp/phase-status.json`

## Goal

Reframe Article6 around pre-verification readiness for project developers.

This lane focuses on faster developer feedback before formal review:

- Quick Check = first document scan
- Projects = readiness workspace
- Methods = methodology and rule source
- Exports = readiness gap report

## Scope

- Create a developer-first readiness roadmap lane.
- Reframe product copy toward readiness, gaps, missing evidence, weak support, follow-up, and recommended fixes.
- Add project-level readiness summaries and readiness gap export CTA.
- Keep the underlying data model compatible with a later VVB workflow.

## Non-goals

- Do not build the VVB workflow yet.
- Do not introduce `verify.article6.org` yet.
- Do not expose VVB-specific UI on the developer-first surfaces.
- Do not claim final verification, approval, compliance, pass/fail, or a final decision.

## Acceptance

- Developer-facing surfaces use readiness-safe language.
- Project detail shows a readiness summary with methodology, uploaded evidence count, top weak or missing items, linked rule references, recommended next action, and readiness export CTA.
- Existing workflows stay compatible with a future VVB lane without exposing that lane yet.
